- **Context:** Building the "query-field chevron popover" with a `ListView`/`Repeater` bound to a JS array (`root.recentSearchesData` from `JSON.parse(controller.recentSearchesJson)`) reliably reported the correct model `count` but never instantiated any delegate items under the offscreen QPA platform used by the GUI test harness (`tests/gui/helpers.py`) — `Repeater.itemAt(0)` / the visual tree stayed empty no matter how long `QCoreApplication.processEvents()` / `QTest.qWait()` ran. Separately, and independently, any `QtQuick.Layouts` (`ColumnLayout`) child whose `visible`/`Layout.preferredHeight` binding changes **before** its `Popup` is first shown gets stuck at 0 height/width forever — Qt skips "polish" for invisible items and never retroactively reruns it once the popup opens, even though the binding's own value is provably correct afterward.
- **Decision:** (1) The popup's `contentItem` is a `Loader` with `active: recentSearchesPopup.visible`, so the whole content tree is destroyed and freshly recreated on every open — this means every binding evaluates for the first time already against the final (post-reload) data, sidestepping the invisible-at-creation layout bug entirely. (2) Reload the recent-searches JS array (`root.reloadRecentSearches()`) synchronously **before** calling `recentSearchesPopup.open()` in the chevron button's `onClicked`, not after — ordering matters because `Loader.active` flips (and its `sourceComponent` is instantiated) synchronously inside the same call stack as `Popup.open()`. (3) Rows are 10 unrolled `component RecentSearchRow: Frame { ... }` instances (`RecentSearchRow { rowIndex: 0 }` … `RecentSearchRow { rowIndex: 9 }`) indexing into `root.recentSearchesData[rowIndex]`, not a data-driven view — this avoids the delegate-incubation-never-completes issue since these are ordinary statically-declared QML objects, not dynamically created ones. Storage still caps at ~20 (`RECENT_SEARCHES_CAP`); the popover simply only *displays* the 10 most recent.
- **Rationale:** Both failure modes are specific to dynamically-created-while-hidden QML content under the offscreen test platform; recreating fresh on each open (Loader) plus avoiding view/delegate-model machinery altogether (static unrolled rows) empirically fixed both, verified via direct QObject-tree walks (`window.findChild`) showing zero delegate children with the ListView/Repeater approach vs. fully-sized, clickable buttons with the static-row approach. A `ListView`/`Repeater` would be more idiomatic and would generalize past 10 items, but was not reliably testable in this codebase's existing offscreen GUI test harness; revisit if the cap ever needs to grow meaningfully past 10 in the popover.
