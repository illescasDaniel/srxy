- **Context:** `develop` already carries the Mach-O `Srxy.app` launcher + `vtool` SDK-26 restamp (Tahoe Liquid Glass) for the online/prefix install path (Trello `geIhdHch` asks for offline parity, on `feature/1.8.0`). `develop` has since diverged heavily from `feature/1.8.0` (NSIS Windows rewrite already landed, `checks.py` gate rewrite, terminal-quit-signal / native-alert / noisy-logging GUI features, etc.) — a full merge/cherry-pick of `develop` would drag in unrelated, un-reviewed 1.8.0-scope changes and conflict with the still-planned "NSIS instead of Inno" item.
- **Decision:** Hand-port only the files needed for the restamp: `install.py` (Mach-O launcher embed/restamp/codesign, `_write_macos_app` rewrite, Darwin `PySide6==6.11.1` pin, QML cache clear), `package_spec.py` (`_packaged_payload_wheel` so offline/fat installers never swap their shipped wheel for a newer PyPI build), `qt_theme.py`'s `prefer_macos_quick_controls_style()` (wired into both `gui/app.py` and `installer/app.py`), the new `resources/macos/` (C launcher source) and `resources/icons/icns.py` (macOS 26+ `iconutil` workaround) packages, `packaging/macos/build-offline.sh` (PySide pin + icns builder) and `smoke-offline.sh` (Quick style assertion), plus the matching tests (`tests/unit/test_macos_app_launcher.py`, `tests/gui/test_installer.py` updates) and the `scripts/macos/repair-prefix-gui.sh` dev tool. Left the Windows NSIS/Inno work, `checks.py` rewrite, and unrelated GUI features (`install_terminal_quit_signals`, `native_macos_alerts_enabled`, `silence_noisy_qt_logging`) out of scope.
- **Rationale:** `write_launcher()` → `_write_macos_app()` is already shared by both the online (`resolve_srxy_install_spec`, PyPI) and offline (`resolve_bundled_or_local_spec` / bundled wheel) install flows via `install_srxy()`, so porting that one path gives the offline PySide bundle the same Liquid Glass chrome with no offline-specific branching needed — the only genuinely offline-specific gap was making sure the offline installer doesn't silently prefer a newer PyPI wheel over its own tested/restamped payload (`_packaged_payload_wheel`) and that the *offline installer wrapper's own* bundled PySide6 build stays pinned to the same version the restamped runtime uses.
- **Also:** bumped `pypdf>=6.15` → `>=6.16.1` — a pre-existing `pip-audit` CVE finding on `feature/1.8.0` (3 known vulns in `pypdf==6.15.0`, unrelated to this task) that blocked a clean quality-gate run; trivial, low-risk version bump, matches what `develop` already carries.
